# LifeOS Mobile — النسخة الجديدة

هذه النسخة تحافظ على صفحات ووظائف LifeOS الحالية، وتضيف طبقة موبايل احترافية فقط.

## ما تغيّر على الهاتف
- الصفحة الرئيسية أصبحت بوابة مباشرة لكل أقسام LifeOS.
- شريط سفلي: الرئيسية، المهام، العادات، الأهداف، حسابي.
- لا يوجد Sidebar على الهاتف ولا زر «المزيد».
- صفحة حسابي فيها الوضع الداكن وإعدادات التنبيهات وتسجيل الخروج.
- زر الجرس أصبح مركز إشعارات فعلي.

## التنبيهات
- المهام: أضف «وقت التذكير» داخل نموذج المهمة.
- العادات: يستخدم حقل «وقت التذكير» الموجود أصلًا.
- الأحداث: اختر بدون تذكير / في وقت الحدث / قبل 10 أو 30 أو 60 دقيقة.
- عند تعديل العنصر تُلغى التنبيهات القديمة وتُجدول الجديدة.
- عند حذف العنصر تُلغى تنبيهاته.
- الضغط على تنبيه Android يفتح القسم المرتبط ويحاول إبراز العنصر نفسه.

## بناء APK على GitHub
المسار `.github/workflows/main.yml` جاهز. بعد رفع المشروع إلى مستودع GitHub، شغّل `Build LifeOS APK` من Actions. الملف الناتج اسمه `LifeOS-Mobile.apk` داخل Artifact باسم `LifeOS-Mobile-APK`.

## ملاحظة Android
Android 13+ يطلب إذن الإشعارات من المستخدم. Workflow يضيف كذلك صلاحية جدولة التنبيهات الدقيقة إلى AndroidManifest أثناء البناء.


## تسجيل Google وLifeOS Pro
تمت إضافة بنية تسجيل Google عبر Supabase + Deep Link، وبنية اشتراكات Android عبر RevenueCat/Google Play Billing.

للتفعيل الفعلي خطوة بخطوة اقرأ: `GOOGLE_AUTH_AND_PRO_SETUP_AR.md`.


## توقيع Android ثابت
Workflow يستخدم GitHub Secret باسم `LIFEOS_DEBUG_KEYSTORE_BASE64` حتى تبقى بصمة APK ثابتة بين كل Build.
البصمة الثابتة الحالية:

`EB:93:BC:15:53:13:12:07:0A:72:8B:B2:F9:53:47:3F:ED:2B:B5:DB`

راجع `STABLE_ANDROID_SIGNING_AR.md` قبل أول Build بهذه النسخة.

## إعلانات Google AdMob — Rewarded Ads فقط
هذه النسخة تستخدم **الإعلانات المكافِئة الاختيارية فقط**. لا يوجد Banner ولا إعلان عند فتح التطبيق ولا إعلان إجباري بين الصفحات.

### فكرة النسخة المجانية
- المستخدم يستعمل الحد المجاني لكل قسم.
- إذا وصل للحد، LifeOS يعرض خيارًا واضحًا: مشاهدة إعلان للحصول على زيادة، أو الترقية إلى LifeOS Pro.
- الحد العام لمكافآت الإعلانات هو **6 مكافآت في اليوم** لكل مستخدم.
- LifeOS Pro يلغي إعلانات المكافآت وحدود الإضافة.
- **القسم الديني مفتوح بالكامل وبدون إعلانات أو حدود.**
- تسجيل الدخل/المصروف، اليوميات، التمارين والوزن، جلسات الدراسة ونتائج الاختبارات يبقى مفتوحًا ولا يحتاج إعلانًا.

### إعداد AdMob الحقيقي قبل النشر على Google Play
1. أنشئ تطبيق Android داخل Google AdMob بالحزمة `com.lifeos.app`.
2. أنشئ **Rewarded Ad Unit واحد** للنسخة الأولى.
3. داخل إعدادات Server-Side Verification للإعلان المكافئ، استخدم رابط Supabase التالي:
   `https://himyddwbgyxohalxlzaz.supabase.co/functions/v1/admob-ssv`
4. أضف GitHub Secret باسم `ADMOB_ANDROID_APP_ID` وضع فيه Android App ID من AdMob.
5. أضف GitHub Secret باسم `VITE_ADMOB_REWARDED_AD_UNIT_ID` وضع فيه Rewarded Ad Unit ID.
6. Workflow يستخدم أرقام Google التجريبية تلقائيًا إذا كان أحد المعرّفين الحقيقيين غير موجود، حتى لا ترسل نسخة الاختبار زيارات إلى إعلان إنتاجي.
7. بعد إضافة **المعرّفين الحقيقيين معًا** ينتقل Workflow تلقائيًا إلى وضع الإنتاج.

### أرقام Google التجريبية المستخدمة في Build الاختبار
- Android App ID: `ca-app-pub-3940256099942544~3347511713`
- Rewarded Ad Unit ID: `ca-app-pub-3940256099942544/5224354917`

لا تغيّر هذين الرقمين يدويًا أثناء التطوير. ولا تستخدم إعلانًا إنتاجيًا لاختبارات متكررة.

### التحقق الآمن من المكافأة SSV
تم نشر Edge Function باسم `admob-ssv` على Supabase. Google ترسل تأكيد المشاهدة إليها، والوظيفة تتحقق من توقيع Google ثم تمنح الزيادة في قاعدة البيانات. العميل يستطيع قراءة مكافآته فقط ولا يستطيع منح نفسه مكافأة دائمة.

مهم: إعلان Google التجريبي يفيد لاختبار فتح/عرض Rewarded Ad على Android، لكنه لا يُستخدم لإثبات وصول SSV الحقيقي. اختبار SSV الدائم يتم من أداة SSV في AdMob أو لاحقًا بوحدة الإعلان الحقيقية في بيئة اختبار صحيحة.

### قبل اعتبار النسخة Production
- تأكد أن `ADMOB_ANDROID_APP_ID` و`VITE_ADMOB_REWARDED_AD_UNIT_ID` موجودان معًا في GitHub Secrets.
- فعّل SSV في AdMob على الرابط أعلاه واستخدم أداة اختبار SSV.
- جرّب حساب Free وحساب Pro على Android حقيقي.
- تأكد أن القسم الديني لا يعرض أي شاشة إعلان.
- راجع صفحة «حسابي > خصوصية الإعلانات» عندما تطلب Google إظهار خيارات الخصوصية.
